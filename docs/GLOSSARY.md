# Glossary — CSA Assurance Planner

Educational terms used in this prototype. They are not regulatory determinations.

| Term | Meaning in this repo |
|---|---|
| **Intended use** | What the software is for in the fictional process (e.g. audit-trail review support). |
| **Process / product risk** | Simple educational tier (`low` / `medium` / `high`) used to scale assurance depth. |
| **GAMP category** | Illustrative software category (`1`, `3`, `4`, `5`) recorded on the assessment. |
| **Scripted** | Higher-formality, pre-defined test steps for higher-risk functions. |
| **Unscripted** | Ad-hoc / exploratory assurance where risk does not justify full scripts. |
| **Critical thinking** | Assurance that relies on qualified review rather than rote scripts. |
| **Record / signature** | Planning flags that a function produces a quality record or a signature meaning. |
| **Assurance item** | One requirement-level row: function, CSA class, rationale, and test strategy. |
| **Review** | QA/CSV-style decision (`approve` or `needs_revision`) with a comment. |
| **Audit log** | Append-oriented application history with server-generated UTC timestamps. |

None of these fields certify fitness for a real manufacturing or QMS process.
